# MCFinder Engine 0.4

Движок владеет перебором сидов, распределением нагрузки, фильтрацией младших
48 бит, раскрытием старших битов, CPU/GPU, статистикой, выводом и checkpoint.
Пользовательский код задаёт условия и возвращает результат.

## Запуск

```sh
cargo build --release --locked

# Человеческий интерфейс
./target/release/mcfinder search --script examples/scripts/ship-mansion.rhai \
  --experimental --mode cpu-and-gpu --cores 8 --ui tui \
  --structure-seeds --upper-count 1 --count 1000000 --output hits.jsonl

# Поток событий одного запуска для интеграции
./target/release/mcfinder search --script examples/scripts/slime-cluster.rhai \
  --cores 4 --count 1000000 --ui backend

# Постоянный backend: команды по stdin, события по stdout
./target/release/mcfinder serve

# Проверка скрипта без перебора
./target/release/mcfinder check-script examples/scripts/ship-mansion.rhai
```

`--ui auto` выбирает TUI только для интерактивного терминала. При перенаправлении
вывода сохраняется режим `plain`: результаты JSONL в stdout, статистика в stderr.
В TUI: Space — пауза/продолжение; стрелки — история; q/Esc/Ctrl+C — остановка,
сохранение завершённого префикса и выход. После нормального завершения результаты
остаются на экране до Enter/q. История содержит последние 200 результатов;
`--output` сохраняет все. Числа обновляются раз в секунду, клавиши и перерисовка
обрабатываются чаще. Терминал восстанавливается при выходе и ошибках интерфейса.
Столбец Locations извлекает именованные координаты `{x, z}` (и `y`, если задан)
из возвращённого скриптом `data`, включая вложенные объекты и массивы. Если их нет,
показывается нативное evidence. Явные координаты скрипта имеют приоритет, поскольку
они могут уточнять независимые свидетельства нативных правил. Расчётная высота
отображается как `base Y≈…`, отдельно от точного Y.

## Скрипты Rhai

```rhai
fn configure() {
    #{version: "26.2", radius: 4096,
      rules: [#{type: "near", a: "mansion", b: "shipwreck", distance: 32}]}
}

fn matches(world, candidate) {
    let sites = candidate.evidence[0].sites;
    let a = sites[0].position;
    let b = sites[1].position;
    let d2 = distance2(a.x, a.z, b.x, b.z);
    if d2 > 256 { return false; }
    #{mansion: a, shipwreck: b, distance_squared: d2}
}
```

`configure()` возвращает обычный Query: точную версию, радиус и массив правил.
`rules: []` разрешён для самостоятельных предикатов. `matches(world, candidate)`
возвращает `false` для отклонения, `true` для принятия либо map для принятия с
дополнительным полем `hit.data`. В map можно вложить массивы и другие JSON-данные.
Тип возврата, исключения и превышение лимитов проверяются: ошибка останавливает
запуск и не продвигает checkpoint мимо непроверенной основы.

Скрипт компилируется один раз за запуск и разделяется между рабочими потоками.
Выполняются функции `configure`, `matches` и ваши функции-помощники. Глобальные
выражения не выполняются; храните константы и переменные внутри функций.
`print`/`debug` подавляются, чтобы не нарушать backend-протокол. Файловый импорт и
`eval` отключены. Состояние одного вызова не переносится на другие сиды.

Параметры `--version`, `--radius` и дополнительные `--near`/`--spawn-near`
применяются к плану после configure. Нативные правила объединяются через AND.
Каждое правило выбирает первый подходящий экземпляр независимо от других правил.
Если скрипту нужны другие экземпляры или связанные условия, он может перечислить
позиции через `world.structures` и вернуть выбранные координаты в `data`.

### API world

| Выражение | Результат |
| --- | --- |
| `world.seed` | Знаковый i64-сид, пригодный для Minecraft |
| `world.seed_bits()` | Полные 64 бита как десятичная строка |
| `world.lower48()` / `world.upper16()` | Младшие 48 / старшие 16 бит |
| `world.position("village", rx, rz)` | Начальная позиция в регионе либо `()`; без проверки биома |
| `world.viable("village", x, z)` | Допустимость биома для структуры в данной точке |
| `world.structures("village", x, z, radius, true)` | Позиции в круге; последний флаг включает проверку биомов |
| `world.biome(x, y, z)` | Числовой ID биома Cubiomes |
| `world.spawn_estimate()` | Приблизительная позиция спавна `{x,z}` |
| `world.slime_chunk(cx, cz)` | Slime chunk по координатам чанка |
| `world.mansion_base_y_estimate(x, z)` | 1.18+: минимум оценки `128 × climate depth` в четырёх точках размещения особняка с учётом поворота. Это оценка рельефа, не фактический Y поверхности или здания; плотностный шум и блоки не генерируются. |
| `world.high_mansion(min_y, regions)` | 1.18+: нативный перебор регионов `[-regions, regions)` по обеим осям, `regions=1..16`. Возвращает первый биомный кандидат с оценкой основания ≥ `min_y` или `()`. Отбрасывает низкие позиции после первой неподходящей точки, без скриптового цикла; результат содержит `mansion`, `estimated_base_y`, `height_validation`. |
| `distance2(x, z, a, b)` | Квадрат расстояния в блоках, без округления |

Координаты блоков и регионов — разные единицы. Имена структур совпадают с JSON Query.
Для ID биомов используйте enum BiomeID в `vendor/cubiomes/biomes.h`.
Встроенный лимит — 100000 Rhai-операций на вызов, максимум 32 уровня вызовов,
4096 элементов массива и 100000 нативных проб мира на сид. В backend/Rust SDK
`ScriptSpec.max_operations` можно увеличить до 10000000. Бесконечный скрипт
завершается ошибкой, а не блокирует движок навсегда.

Примеры: `examples/scripts/ship-mansion.rhai`, `slime-cluster.rhai`,
`village-cluster.rhai`.

## Что оптимизирует движок

1. Компиляция Query в нативный план и скрипта в AST один раз на запуск.
2. Выбор более редкой структуры для перебора пары и только соседних регионов второй.
3. Порядок нативных проверок по стоимости: дешёвые фильтры до дорогого спавна;
   номера evidence сохраняют исходные номера правил.
4. В гибридном режиме — целочисленный OpenCL-отсев позиций на GPU с автоматическим
   профилем Apple/NVIDIA/Generic. Нативный CPU-код оптимизируется при сборке под чип.
5. Генерация биомов и пользовательский предикат только после прохождения геометрии.
6. Переиспользование геометрии основы при раскрытии старших 16 бит.
7. Автоматический размер пакета по стоимости плана и измеренному времени раунда
   (цель около 250 мс, минимум заполнения CPU-пула); `--batch-size` фиксирует размер.
8. Пул CPU-потоков, ограниченные пакеты результатов и отдельные счётчики на линии
   кеша рабочих потоков; полные генераторы мира не разделяются между потоками.

Произвольный Rhai/Rust-код выполняется на CPU. GPU ускоряет декларативные нативные
правила; автоматической трансляции произвольного скрипта в CUDA/OpenCL нет.
Если нативных правил нет, используйте `cpu-only`. Это явно проверяется при запуске.
Многопоточность, размер пакета, профили и перебор не нужно реализовывать в скрипте.

Движок не анализирует произвольный AST для устранения ненужных проверок:
все заданные нативные правила выполняются до `matches()`, а вызовы внутри скрипта
идут в его порядке. Генератор при первом запросе на сид инициализирует полный
набор шумов биомов, даже если фильтру высоты нужна лишь часть. Нативный план и
скрипт используют отдельные кеши генераторов. Пакет вычисляется параллельно
до выдачи результатов, поэтому при `--max-results` часть проверок после последнего
выданного сида может оказаться лишней; checkpoint сохраняет безопасный префикс.

## JSONL protocol v1

Каждая команда — одна JSON-строка с уникальным `id`. Backend держит один активный
поиск на процесс; для независимых одновременных поисков запускайте несколько
процессов, при необходимости с `shards`/`shard_id`. stdout содержит только JSONL.

```json
{"cmd":"capabilities","id":"caps"}
{"cmd":"start","id":"job-1","max_results":10,"settings":{"query":{"version":"26.2","radius":4096,"rules":[{"type":"near","a":"mansion","b":"shipwreck","distance":16}]},"experimental":true,"mode":"cpu-and-gpu","cores":8,"structure_seeds":true,"upper_count":1,"count":"1000000"}}
{"cmd":"status","id":"status-1"}
{"cmd":"pause","id":"pause-1"}
{"cmd":"resume","id":"resume-1"}
{"cmd":"cancel","id":"cancel-1"}
{"cmd":"shutdown","id":"shutdown-1"}
```

`start.settings.script` может содержать `{source, name?, max_operations?}` вместо
query. Текст source — полный Rhai-скрипт. Если задана и query, и script, явная query
переопределяет configure, а matches продолжает работать. `compile` принимает
`{cmd:"compile", id, script}` и возвращает Query и SHA-256 исходника без поиска.
`start` дополнительно принимает `checkpoint`, `append` и `max_results`.
`restore` принимает `checkpoint`, необязательные `cores`, `mode`, `gpu_index` и
`max_results`; команда `resume` только снимает паузу текущего поиска.

В settings `start` и `count` принимают целые JSON-числа либо десятичные строки.
Для точных 64 бит из JavaScript используйте строки. Знаковая строка start допустима.
Счётчики состояния сериализуются десятичными строками; скорости — JSON-числами.
`upper_count` выбирается автоматически: 65536 для раскрытия основ с биомами,
1 для placement-only и обычного перебора. Явное значение переопределяет выбор.
`cores` и batch можно опустить; выбор устройства и правила совпадают с CLI.
Нулевые count/cores/upper_count/max_results не являются «бесконечностью».

События поиска: `started`, `ready`, `progress`, `match`, `error`, `finished`.
Они содержат `protocol:1`, возрастающий `seq` и `job_id`, равный id запуска.
Ответы управления содержат `id` команды и при необходимости `job_id`.
`ready` сообщает фактические профили, число потоков, SHA-256 скрипта и `native_order`.
`finished.summary.status` — `complete`, `limit_reached`, `cancelled` или `failed`.
Ошибка скрипта даёт error и затем finished; backend после этого принимает новый поиск.
Нельзя запускать второй поиск, пока первый ещё работает.

Состояние приходит раз в секунду из отдельного потока, включая паузу и долгую
проверку внутри большого пакета. Дополнительно status возвращает снимок немедленно.

| Поле state | Значение |
| --- | --- |
| `bases_tested` | Основы/полные сиды, обработанные работниками в текущем запуске |
| `seeds_evaluated` | Полные сиды, дошедшие до нативной проверки после геометрии |
| `geometry_passed` | Основы, прошедшие геометрический фильтр |
| `scripts_evaluated` | Вызовы matches |
| `matches_found` | Принятые предикатом кандидаты, включая опережающую работу пула |
| `results_emitted` | Результаты, переданные в вывод; именно это TUI показывает как Results |
| `bases_committed` | Основы, полностью завершённые в текущем запуске |
| `completed_before_run` | Основы, завершённые до восстановления checkpoint |
| `cursor` | Безопасная граница для продолжения перебора |
| `total_bases` | Количество основ выбранного шарда |
| `bases_per_second`, `seeds_per_second` | Скорость за последний период обновления |
| `average_bases_per_second` | Средняя скорость с начала запуска |
| `elapsed_seconds`, `phase`, `paused`, `cancelled` | Время и состояние поиска |

Частичный раунд может уже дать результаты, но ещё не продвинуть cursor.
При лимите результатов/отмене matches_found может быть больше results_emitted.
Пауза и отмена кооперативные: начатый вызов C/Rust завершается прежде, чем поток
останавливается. Heartbeat при этом продолжает работать. Потребитель должен
постоянно читать stdout: медленный pipe создаёт обратное давление и не позволяет
гарантировать доставку сообщений каждую секунду. Закрытие stdin отменяет поиск
и сохраняет завершённый префикс; для разового запуска без команд есть --ui backend.
Пример клиента без зависимостей: `python3 examples/backend_client.py`.

## Rust SDK и расширения

`src/lib.rs` экспортирует engine, events, script, backend, plan и protocol.
`engine::run(Settings, RunOptions, Control, Observer)` не устанавливает сигнальные
обработчики и не пишет в stdout/stderr. Его можно вызывать несколько раз и из
собственных потоков. Создавайте новый Control на каждый запуск. Observer должен
принимать события из рабочих/отчётного потоков и быстро возвращать управление.

`Control.pause()`, `resume()`, `cancel()` и `snapshot()` доступны из другого потока.
`RunOptions.filter: Arc<dyn SeedFilter>` подключает произвольный Rust-предикат или
собственный поставщик данных мира; `evaluate(seed, candidate)` возвращает None для
отклонения или Some(JSON) для принятия. Запускайте пример:

```sh
cargo run --release --example sdk
```

Встроенный генератор даёт структуры, биомы, slime chunks и оценку спавна.
**Блоки, полная геометрия построек, высота рельефа и лут не реализованы.** Скрипт не
получает выдуманные значения для этих свойств. Для таких поисков нужно расширить
поставщика world-data через Rust SDK. Новые версии от 1.21.5 до 26.3 остаются
экспериментальными, а результаты — кандидатами до подтверждения в игре.

## Checkpoint и проверка

Checkpoint схемы 3 сохраняет разрешённый Query, параметры и сам текст скрипта с
лимитами: изменение .rhai на диске не меняет восстановленный поиск. Проверяется
версия движка. Старые checkpoint 0.2 несовместимы. Вывод сбрасывается перед курсором;
последняя незавершённая основа может проиграться повторно. Гарантия at least once,
дедупликация по seed_bits. Нельзя разделять один checkpoint между процессами.

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked gpu_matches_cpu_geometry_all_profiles -- --ignored
```

### Новые функции для Rhai и собственный backend-хост

`script::ScriptExtension` регистрирует функции в Rhai Engine до компиляции AST.
Передайте расширения через `RunOptions.extensions`. Свой backend-хост может вызвать
`protocol::serve_with_extensions(...)`: те же функции будут доступны скриптам,
поступающим по JSONL, а capabilities перечислит имена расширений.

Пример `examples/sdk_script.rs` добавляет метод `world.seed_mod(n)`:

```sh
cargo run --release --example sdk_script
cargo run --release --example sdk_script -- serve
```

Вместо этого метода можно привязать собственный генератор блоков, лута или другой
источник world-data. Объект World предоставляет `seed_u64()`, `version_id()`,
`is_cancelled()` и `consume_probes(n)` для кооперативной отмены и ограничения работы.
Rust-привязки являются доверенным нативным кодом: их длительные циклы должны сами
наблюдать отмену. Rhai re-export доступен как `mcfinder::rhai` для совпадения типов.

Checkpoint сохраняет имена расширений и SeedFilter. Восстановление требует того же
хоста и тех же провайдеров; обычный CLI не продолжит такой checkpoint молча без
пользовательской логики. Используйте версионированные имена вроде `blocks@1`;
сопоставление имён не является хешированием машинного кода нативного провайдера.
