# MCFinder

Версия 0.4: расширяемый движок со скриптами Rhai, Rust SDK, TUI и постоянным
JSONL backend. [Документация движка и API](ENGINE.md).

```sh
./target/release/mcfinder search --script examples/scripts/ship-mansion.rhai --experimental --ui tui
./target/release/mcfinder serve
```

Консольный поисковик **кандидатов** в сиды Minecraft Java Edition на Rust с Cubiomes.
Многопоточный CPU, настоящий GPU-отсев через OpenCL, профили Apple/NVIDIA, перебор
48-битных основ и 64-битных миров, JSON-запросы, JSONL, checkpoint и шардинг.

**Предел точности:** сейчас проверяются позиции начала структур и допустимость
биомов. Расстояние считается в плоскости X/Z между этими позициями, а не между
крайними блоками построек. Спавн — оценка Cubiomes, без Y, высоты крыши, полного
рельефа и случайного смещения игрока при появлении. Поэтому пример «спавн прямо
на крыше пирамиды» пока реализован как поиск кандидатов рядом с пирамидой;
гарантировать крышу этот движок не умеет. Для точного расстояния между границами
деревни и особняка также потребуется генерация их частей в vanilla-совместимом
движке. Найденные сиды нужно проверять в игре выбранной версии.

## Сборка

Нужны Rust с edition 2024 и C-компилятор. Cubiomes и патчи включены в репозиторий;
скачивания во время сборки нет. Cargo-зависимости закреплены в `Cargo.lock`.

```sh
cargo build --release --locked
./target/release/mcfinder --help
./target/release/mcfinder devices
./target/release/mcfinder versions
```

Под конкретный CPU, включая C-часть:

```sh
# Чип и архитектура определяются автоматически: Apple/Intel/AMD/ARM
./scripts/build-native.sh
./target/native/release/mcfinder devices
```

При обычной сборке C-ядро автоматически оптимизируется под CPU машины сборки:
Apple Silicon, ARM Linux или Intel/AMD. Cross-compilation использует переносимый C-путь.
Скрипт дополнительно включает `target-cpu=native` для Rust; вручную выбирать
профиль не требуется. Полученный бинарник предназначен для CPU машины сборки.
Для распространения между разными CPU: `cargo build --release --no-default-features`.
`devices` и запуск поиска показывают фактический тип CPU-сборки.
В C сохранён `-fwrapv`; `fast-math` не включается, чтобы не менять биомы.

## Примеры

Особняк и деревня с расстоянием между **начальными позициями** до 10 блоков,
в квадрате X/Z от −4096 до +4096, на восьми рабочих потоках CPU:

```sh
./target/release/mcfinder search \
  --version 1.18.2 --near mansion:village:10 --radius 4096 \
  --mode cpu-only --cores 8 --start 0 --count 100000000 \
  --output hits.jsonl --checkpoint search.checkpoint.json
```

Обе позиции должны находиться в квадрате. Это ограниченный участок мира;
поиск «где-нибудь в бесконечном мире» конечным перебором не выполняется.
Позиции обычно кратны 16, поэтому порог 10 очень строгий и не равнозначен
«между стенами 10 блоков». Отсутствие результатов допустимо.

Приблизительный мировой спавн рядом с пирамидой:

```sh
./target/release/mcfinder search \
  --version 1.18.2 --spawn-near desert_pyramid:24 --radius 512 \
  --mode cpu-only --cores 8 --count 100000 --max-results 10
```

GPU и экспериментальная версия 26.3:

```sh
./target/release/mcfinder search \
  --version 26.3 --experimental --near mansion:village:10 \
  --mode cpu-and-gpu --gpu-index 0 --cores 4 \
  --batch-size 65536 --count 100000000 --output hits.jsonl
```

Есть ровно два режима: `--mode cpu-only` (по умолчанию) и `--mode cpu-and-gpu`.
В обоих `--cores N` задаёт положительное число CPU-потоков, не больше доступных
логических ядер. Без `--cores` используются все доступные; привязки к физическим
ядрам нет. `devices` выводит устройства и автоматически определённые профили.
`--gpu-index` доступен только в `cpu-and-gpu`; без него берётся первая GPU.
Ручного `--gpu-profile` нет: Apple/NVIDIA/Generic выбирается по vendor карты.
При выборе гибридного режима без доступного OpenCL GPU программа завершится с ошибкой.
На Linux/Windows нужен OpenCL-драйвер производителя, на macOS используется
системный OpenCL. CPU-режим OpenCL вообще не загружает.

## Профили устройств

| Профиль | Что меняется |
| --- | --- |
| CPU Apple Silicon | Автоматическая компиляция C-ядра под реальный Apple CPU |
| CPU Intel/AMD/ARM | Автоматическая компиляция C-ядра под реальный CPU машины сборки |
| GPU `apple` | Константный 48-битный LCG в целочисленном ядре; группы до 64 потоков |
| GPU `nvidia` | LCG разложен на 32-битные операции и `mul_hi`; группы до 128 потоков |
| GPU `generic` | Переносимый целочисленный OpenCL LCG; группы до 64 потоков |

Профиль GPU выбирается автоматически при каждом запуске и возобновлении;
названия в таблице описывают внутренние пути, а не ручные параметры.

Размер группы дополнительно ограничивается лимитом скомпилированного ядра.
Это специализированные OpenCL-пути; CUDA- и Metal-бэкендов здесь нет.
GPU выполняет геометрический отсев, CPU проверяет прошедшие основы, биомы и спавн.
Для outpost GPU допускает лишние кандидаты; точное ограничение частоты проверяет CPU.
Размер пакета подбирается автоматически по стоимости плана и измеренному времени
обработки, с ограничением памяти. Для скриптов начало поиска использует небольшие пакеты. Для ручного тюнинга есть
`--batch-size 1..1048576`; большой пакет увеличивает задержку checkpoint.
Выгода GPU зависит от запроса; профиль NVIDIA математически сверен на Apple GPU,
но скорость на физической NVIDIA в этой среде не измерялась.

## Сложные запросы

```sh
./target/release/mcfinder preset mansion-village > query.json
./target/release/mcfinder search --config query.json --cores 8 --count 1000000
```

```json
{
  "version": "1.18.2",
  "radius": 4096,
  "rules": [
    {"type": "near", "a": "mansion", "b": "village", "distance": 160},
    {"type": "spawn_near", "structure": "desert_pyramid", "distance": 128}
  ]
}
```

Все правила объединяются через AND. Каждое правило может найти собственные
экземпляры структур; общей переменной «эта же деревня» между правилами нет.
Для пары одной структуры с самой собой требуются два разных экземпляра.
Повторяемые `--near`/`--spawn-near` добавляют правила к конфигу;
`--version` и `--radius` переопределяют поля конфига. Версия обязательна в аргументах
или JSON, скрытой версии по умолчанию нет. Неизвестные JSON-поля запрещены.

Структуры: `desert_pyramid`, `jungle_temple`, `swamp_hut`, `igloo`, `village`,
`ocean_ruin`, `shipwreck`, `monument`, `mansion`, `outpost`, `ruined_portal`,
`ancient_city`, `trail_ruins`, `trial_chambers`. Недоступные для версии структуры
отклоняются до начала поиска. Только Overworld и стандартная генерация мира.

## Огромные диапазоны

Обычный режим проверяет `count` полных сидов, начиная со `start`.
`--start` принимает signed i64 или unsigned u64 с тем же битовым представлением.
Переполнение диапазона запрещено.

```sh
# Перебирать основы из младших 48 бит, раскрывая только прошедшие геометрию
# в полные миры с верхними 16 битами 0..65535.
./target/release/mcfinder search --version 1.18.2 --near mansion:village:10 \
  --structure-seeds --start 0 --count 1000000 \
  --upper-start 0 --upper-count 65536 --cores 8 --output hits.jsonl

# Только дешёвые позиции, без биомов: быстрый список кандидатов
./target/release/mcfinder search --version 1.18.2 --near mansion:village:10 \
  --structure-seeds --upper-count 1 --placement-only --count 100000000
```

Геометрия зависит от младших 48 бит; биомы — от полного сида. Геометрия основы
переиспользуется при раскрытии старших битов. Большое раскрытие параллелится
по CPU-потокам. Для ограничения памяти объём раунда уменьшается так, чтобы хранить
не более 65536 результатов; полный диапазон старших битов увеличивает время раунда.
`--placement-only` несовместим с правилами спавна. При нём по умолчанию используется
один вариант старших битов, чтобы не выдавать 65536 одинаковых размещений.
`--upper-start`/`--upper-count` доступны только с `--structure-seeds`.
`count` должен быть положительным и считает основы,
а не количество полных миров после раскрытия.

Разделение одного диапазона между несколькими машинами/процессами:

```sh
# На первом процессе; на остальных shard-id 1, 2, 3
./target/release/mcfinder search --version 1.18.2 --near mansion:village:10 \
  --count 1000000000 --shards 4 --shard-id 0 --cores 4
```

Каждый процесс обрабатывает смещения `shard-id + k * shards` внутри общего
диапазона. У процессов должны быть разные файлы вывода/checkpoint.

## Остановка, вывод и возобновление

```sh
./target/release/mcfinder resume search.checkpoint.json --cores 8
```

Ctrl+C завершает поиск с сохранением завершённых основ. Checkpoint хранит
версию движка, запрос, диапазон, устройство, путь вывода и следующую основу.
При resume параметры поиска берутся из checkpoint, включая ранее выбранное число
потоков. Его можно изменить через `--cores N`; режим — через `--mode cpu-only`
или `--mode cpu-and-gpu`, карту — через `--gpu-index`. Профиль GPU определяется
заново на текущей машине. Лимит `--max-results N` относится только к текущему запуску;
без него лимита нет. Нулевые значения для count/cores/batch-size/max-results запрещены.
Завершённый checkpoint — безопасный no-op. Checkpoint старых схем 0.1/0.2 несовместимы с 0.3.

Новый поиск создаёт новый JSONL-файл. Если файл уже есть, для осознанного
добавления результатов нужен `--append`; при resume добавление выполняется автоматически.
Если сохранённый файл результатов исчез, resume останавливается с ошибкой.
JSONL записывается до продвижения checkpoint. При остановке внутри основы,
лимите результатов или сбое последняя основа может проиграться повторно.
Гарантия — **at least once**: для уникальности используйте `seed_bits`.
Checkpoint записывается через временный файл и rename; результаты сбрасываются
в файл перед сохранением курсора. Это не транзакция при потере питания файловой системы.
Не запускайте два процесса с одним checkpoint. Отдельный stdout-поток не может
гарантировать, что внешний потребитель сохранил результаты.

Каждая строка содержит `seed` (знаковая строка для ввода в Minecraft), `seed_bits`
(беззнаковая строка), версию, `validation`, `experimental`, спавн и найденные
позиции/дистанции по каждому правилу. Числа сидов хранятся строками, чтобы JSON/JS
не теряли биты. `placement_candidate` не проверяет биомы;
`biome_candidate` проверяет биомы, но не полную генерацию блоков.
В режиме plain прогресс и скорость идут в stderr, результаты JSONL — в stdout.
Режим backend выводит типизированные события, TUI показывает интерактивный экран.

## Версии и точность

`versions` перечисляет ровно поддерживаемые профили. Используются точные
названия патчей: например `1.8.9`, `1.12.2`, `1.18.2`, `1.20.6`,
`1.21.1`, `1.21.3`, `1.21.4`. Произвольный другой патч не подменяется ближайшим.
Профили от `1.21.5` до `26.3` требуют `--experimental`: это сторонние изменения
таблиц биомов/правил, а не подтверждённая vanilla-совместимость каждой версии.
Даже upstream Cubiomes не заменяет полный игровой генератор.

## Проверки и замеры

```sh
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
# Нужен доступ к настоящему GPU; отсутствие GPU является ошибкой этого теста
cargo test --locked gpu_matches_cpu_geometry_all_profiles -- --ignored --nocapture
```

Проверки покрывают полный перебор против поиска соседних регионов, отрицательные
координаты, младшие 48 бит, границы версий, GPU/CPU, число потоков, шардинг,
checkpoint/resume, старшие биты и ошибки ввода. Совпадение с Cubiomes проверяет
реализацию поиска; оно не подтверждает полную генерацию структур в игре.

Замер базовой сборки 0.1.0 на Apple M2 Pro, версия 1.18.2, миллион сидов,
`mansion:village:10`, квадрат ±4096, 4 CPU-потока, с проверкой биомов:
CPU — 0,719 с (~1,39 млн основ/с), Apple GPU + CPU — 0,733 с (~1,36 млн основ/с),
batch GPU 65536. Совпали 32564 прошедшие геометрию основы, итоговых кандидатов 0.
Поиск по спавну существенно тяжелее: тот же CPU, 1000 сидов, пирамида до 24 блоков,
квадрат ±512 — 0,879 с. Это локальные наблюдения, не обещание такой скорости
для любых условий или NVIDIA.

Исходники и лицензии зависимого C-кода: [vendor/README.md](../vendor/README.md).

## Готовый релиз

Для сборки архива под текущую машину: `./scripts/package-release.sh`.
Архив, контрольная сумма, бинарник, примеры и лицензии находятся в `dist/`.
Это native-сборка под CPU машины сборки; GPU определяется при запуске.

Проверенный запуск релиза 0.2.0 (через собственный поисковик, без стороннего
поиска сидов): Java 26.2, сид `7104`, особняк X=-2064 Z=-2192, корабль
X=-2064 Z=-2176. Начальные позиции находятся в 16 блоках друг от друга.
Использовались `--structure-seeds --upper-count 1 --near mansion:shipwreck:16`
и режим `cpu-and-gpu`, 8 CPU-потоков, автоматический профиль Apple M2 Pro.
Это кандидат по позициям и биомам экспериментального профиля 26.2; геометрия
построек и высоты блоков не подтверждены.
