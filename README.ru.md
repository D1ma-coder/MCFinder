**Движок на Rust для поиска кандидатов в сиды Minecraft Java.** Опишите условия в скрипте — движок займётся перебором, потоками CPU, фильтрацией на GPU, статистикой, результатами и сохранением прогресса.

Корабль рядом с особняком. Деревня у спавна с полезными структурами вокруг. Особняк на необычно высоком расчётном рельефе. Один движок работает и в терминале, и внутри вашего приложения или сервиса.

> Проверяются начальные позиции структур и биомы. Полные блоки, лут и границы построек не генерируются. Высота и спавн приблизительные. Профили **от 1.21.5 до 26.3 экспериментальные**. Результаты требуют проверки в игре нужной версии.

## Что умеет движок

| Возможность | Практическая польза |
|---|---|
| Скрипты Rhai | `configure()` задаёт план, `matches()` уточняет кандидата; компиляция один раз |
| Нативный планировщик | Редкая структура первой, только соседние регионы второй, дешёвые проверки перед спавном |
| CPU и GPU | `cpu-only` или OpenCL-отсев позиций плюс CPU-проверки; число потоков задаётся в обоих режимах |
| Автовыбор профиля | Нативная сборка C под CPU; Apple/NVIDIA/Generic GPU по производителю устройства |
| Младшие 48 бит | Геометрия основы переиспользуется при раскрытии верхних 16 бит |
| TUI | Метрики раз в секунду, числа K/M/B/T, читаемое время, координаты, пауза и продолжение |
| JSONL backend | Долгоживущий процесс: start/status/pause/resume/cancel/restore/shutdown |
| Долгие задачи | Адаптивные пакеты, ограниченная память результатов, checkpoint и шардинг |
| Rust SDK | Нативные предикаты и собственные поставщики данных мира |
| Точные сиды | Десятичные строки в JSON сохраняют все 64 бита |

### Почему это быстро

```text
диапазон -> геометрия структур -> необязательный отсев GPU
         -> CPU: биомы и спавн -> скомпилированный скрипт -> результат
```

Большинство сидов отбрасывается до дорогих проверок. План учитывает размер регионов и стоимость правил, а геометрия 48-битной основы не пересчитывается для каждого набора верхних битов. Специализированный поиск высоты выполняет цикл нативно и прекращает оценку особняка на первой слишком низкой точке размещения.

C-ядро сохраняет нужную целочисленную арифметику без `fast-math`. GPU использует целочисленные пути Java-совместимого размещения; биомы проверяет CPU. Реальный профиль устройства виден в TUI и событиях backend.

**Ускорение зависит от задачи.** Произвольный скрипт не переводится автоматически в GPU-код. GPU не всегда выгоднее CPU. Инициализация генератора пока готовит полный набор шумов биомов. Независимые нативные правила могут выбрать разные экземпляры структур — общую деревню или особняк связывайте скриптом. [Точность и ограничения](docs/GUIDE.ru.md#производительность-и-точность).

## Реальные бенчмарки

[Отчёт](benchmarks/README.md) содержит команды, аппаратную конфигурацию, медианы, разброс, сырые измерения и контрольные суммы результатов. Машина — **Apple M2 Pro**; число потоков указано для каждого сценария.

Ранее выполненное сравнение на одинаковых 100 000 сидов и 10 потоках:

| Фильтр особняка с расчётным Y ≥150 | Скорость | Время |
|---|---:|---:|
| Цикл регионов в Rhai | 13 833 сидов/с | 7,229 с |
| Нативный цикл и ранний отсев | 45 872 сидов/с | 2,180 с |

**Ускорение в 3,32 раза, все пять результатов полностью совпали.** Это результат конкретного фильтра, а не универсальный множитель. В воспроизводимом наборе отдельно измеряются геометрия, биомы, раскрытие верхних битов, GPU и slime chunks. Скорость физической NVIDIA и Windows здесь не измерялась.

## Быстрый старт

Скачайте и распакуйте архив из [Releases](https://github.com/D1ma-coder/MCFinder/releases/latest), откройте терминал в его папке:

```sh
./mcfinder devices
./mcfinder search --script examples/scripts/high-mansion.rhai \
  --experimental --mode cpu-only --cores 8 --ui tui \
  --count 1000000000 --max-results 3 \
  --output mansions.jsonl --checkpoint mansions.checkpoint.json
```

В Windows используйте `.\mcfinder.exe`; в PowerShell вводите команду одной строкой. Примеры и документация входят в архив. Бинарники без цифровой подписи; macOS-сборки не нотарифицированы. Для CPU-only OpenCL не нужен; для GPU требуется совместимый драйвер, на macOS используется системный OpenCL.

**Управление:** Space — пауза/продолжение; ↑/↓ — история; q/Esc/Ctrl+C — остановка с сохранением. После завершения Enter/q закрывает экран.

```sh
./mcfinder resume mansions.checkpoint.json --cores 8 --ui tui
```

Готовые сборки: **Windows x64, macOS Apple Silicon, macOS Intel**. Они используют переносимые настройки CPU. Для максимального тюнинга под свой чип соберите проект локально.

## Скрипт вместо своего переборщика

```rust
// Оценка рельефа, не полная генерация мира
fn configure() { #{version: "26.2", radius: 5120, rules: []} }
fn matches(world, candidate) {
    let result = world.high_mansion(170.0, 4);
    if result == () { return false; }
    result
}
```

`high_mansion()` нативно перебирает сетку 8×8 регионов и возвращает первый биомный кандидат, координаты и оценку основания. Фильтр рельефа работает на CPU. Пример запроса с GPU-отсевом геометрии:

```sh
./mcfinder search --version 1.18.2 --near mansion:village:10 \
  --radius 4096 --mode cpu-and-gpu --cores 8 \
  --structure-seeds --upper-count 256 --count 1000000 \
  --max-results 3 --output pairs.jsonl
```

Расстояния — между **начальными позициями X/Z**, обе структуры должны попадать в квадрат поиска. [API скриптов](docs/GUIDE.ru.md#скрипты-и-api) · [Примеры](examples/scripts).

## Использование в других проектах

**Любой язык:** запустите `mcfinder serve`, отправляйте по одной JSON-команде на строку stdin и непрерывно читайте события stdout. Отдельного HTTP-сервера или SDK не требуется.

```json
{"cmd":"start","id":"job-1","max_results":3,"settings":{"query":{"version":"1.18.2","radius":4096,"rules":[{"type":"near","a":"mansion","b":"village","distance":10}]},"mode":"cpu-only","cores":4,"count":"1000000"}}
{"cmd":"status","id":"status-1"}
{"cmd":"pause","id":"pause-1"}
{"cmd":"resume","id":"resume-1"}
```

События `started`, `ready`, `progress`, `match`, `error`, `finished`. Статистику раз в секунду публикует отдельный поток даже во время долгой проверки или паузы. Медленный потребитель stdout создаёт обратное давление.

- Python и сервисы: [готовый клиент без зависимостей](examples/backend_client.py).
- Node.js: [пример subprocess и правила точной передачи сидов](docs/GUIDE.md#backend-integration).
- Rust: [SDK](examples/sdk.rs), [расширение Rhai и собственный backend-хост](examples/sdk_script.rs). Подключайте Git-зависимость с тегом релиза; crate ещё не опубликован на crates.io.
- Блоки, лут и другая генерация: добавьте свой world-data provider через `SeedFilter` / `ScriptExtension`. Это точки расширения, а не встроенные возможности.

Checkpoint сохраняет запрос, текст скрипта и идентичности расширений. Восстановление — **at least once**, удаляйте повторы по `seed_bits`. Один процесс backend держит одну активную задачу; для распределения используйте несколько процессов и шардинг.

## Сборка и тестирование

Нужны stable Rust и C-компилятор: Xcode Command Line Tools на macOS, MSVC C++ Build Tools на Windows, GCC/Clang на Linux.

```sh
git clone https://github.com/D1ma-coder/MCFinder.git
cd MCFinder
cargo build --release --locked
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

Cubiomes и патчи включены в исходники. Cargo-зависимости скачиваются при первой сборке. Обычная сборка настраивает C под CPU машины сборки; cross-compilation и `--no-default-features` используют переносимый C-путь.

```sh
# macOS/Linux: тюнинг Rust и C под текущий CPU
./scripts/build-native.sh
# Для распространения между разными CPU
cargo build --release --locked --no-default-features
```

[Release workflow](.github/workflows/release.yml) собирает и тестирует Windows и обе архитектуры macOS, прикладывает документацию, примеры, лицензии и SHA-256. CI также проверяет Linux. Аппаратные GPU-тесты запускаются отдельно.
