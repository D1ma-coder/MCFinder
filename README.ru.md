MCFinder — инструмент на Rust для поиска сидов Minecraft Java Edition по заданным условиям. Например, можно найти деревню рядом со спавном, корабль возле особняка или особняк на высоком рельефе.

Условия задаются параметрами командной строки или скриптом. Инструмент перебирает сиды, показывает скорость и результаты в терминале, сохраняет прогресс. Его также можно запустить как backend для другого приложения.

Поддерживаемые профили версий — от 1.8.9 до 26.3; полный список выводит команда `versions`. Профили от 1.21.5 требуют `--experimental`. Сейчас проверяются позиции структур и биомы. Высота и спавн определяются приблизительно; блоки, лут и границы построек целиком не генерируются.

## Установка

Архивы публикуются в [Releases](https://github.com/D1ma-coder/MCFinder/releases) после успешной сборки и тестов:

| Платформа | Название в архиве |
|---|---|
| Windows x64 | `x86_64-pc-windows-msvc.zip` |
| macOS Apple Silicon | `aarch64-apple-darwin.tar.gz` |
| macOS Intel | `x86_64-apple-darwin.tar.gz` |

Распакуйте архив и откройте терминал в его папке. Внутри находятся программа, примеры и документация. Если нужной сборки ещё нет, используйте [сборку из исходников](#сборка-из-исходников).

В примерах ниже команды записаны для macOS/Linux. На Windows замените `./mcfinder` на `.\mcfinder.exe` и вводите команды одной строкой в PowerShell.

Бинарники без цифровой подписи; macOS-сборки не нотарифицированы. Контрольные суммы SHA-256 находятся рядом с архивами. Для поиска на CPU OpenCL не нужен.

## Первый поиск

Найдём до трёх сидов, где деревня находится не дальше 128 блоков от расчётного спавна:

```sh
./mcfinder search --version 1.18.2 --spawn-near village:128 \
  --radius 1024 --count 1000000 --cores 4 --max-results 3 --ui tui \
  --output villages.jsonl --checkpoint villages.checkpoint.json
```

Программа проверит до миллиона сидов, используя четыре потока CPU. `radius` ограничивает квадрат поиска координатами от −1024 до +1024 по X и Z. Сиды и координаты появятся в таблице и сохранятся в `villages.jsonl`.

- **Space** — пауза и продолжение.
- **↑ / ↓** — просмотр результатов.
- **q / Esc / Ctrl+C** — остановка с сохранением прогресса.
- **Enter / q** после завершения — закрыть экран.

Чтобы продолжить остановленный поиск:

```sh
./mcfinder resume villages.checkpoint.json --cores 4 --ui tui
```

Для нового поиска выбирайте новые имена файлов. Для продолжения используйте `resume`.

### CPU и GPU

По умолчанию поиск работает на CPU. `--cores` задаёт число рабочих потоков; если его опустить, используются все доступные логические ядра.

Для запросов по расположению структур можно включить `--mode cpu-and-gpu`. Тогда GPU отбрасывает неподходящие позиции, а CPU проверяет оставшиеся сиды. Профиль Apple/NVIDIA/Generic определяется автоматически. Доступные устройства показывает `./mcfinder devices`.

GPU использует OpenCL и требует совместимого драйвера; на macOS используется системный OpenCL. Выигрыш зависит от запроса. Скрипты без встроенных правил поиска структур, включая пример высокой местности ниже, выполняются в `cpu-only`.

## Свои условия

Простые условия можно задать без скрипта. Например, поиск особняка и корабля с расстоянием до 32 блоков:

```sh
./mcfinder search --version 26.2 --experimental \
  --near mansion:shipwreck:32 --radius 4096 \
  --cores 4 --count 1000000 --max-results 3 --ui tui
```

Расстояния считаются между начальными позициями структур в X/Z. Это не расстояние между их стенами. Повторные `--near` и `--spawn-near` объединяются через AND.

Для более сложных условий есть скрипты Rhai. В этом примере ищется особняк с оценкой основания от Y=170:

```rust
fn configure() {
    #{version: "26.2", radius: 5120, rules: []}
}

fn matches(world, candidate) {
    let result = world.high_mansion(170.0, 4);
    if result == () { return false; }
    result
}
```

`configure()` задаёт параметры поиска. `matches()` принимает или отклоняет сид; возвращённые данные попадают в результат. Здесь `high_mansion()` проверяет сетку 8×8 регионов и возвращает координаты первого подходящего особняка на каждом сиде.

Готовый файл находится в `examples/scripts/high-mansion.rhai`:

```sh
./mcfinder search --script examples/scripts/high-mansion.rhai \
  --experimental --cores 4 --count 100000000 --max-results 3 --ui tui
```

Скрипту не нужно создавать потоки или писать цикл перебора сидов. [Описание API и остальных примеров](docs/GUIDE.ru.md#скрипты-и-api) находится в руководстве.

## Использование в других приложениях

Запустите `mcfinder serve`. Программа читает JSON-команды из stdin и пишет события в stdout — по одной строке на сообщение. Так её можно подключить к Python, Node.js, десктопному приложению или серверу.

Backend умеет запускать поиск, отдавать состояние, ставить на паузу, продолжать, отменять и восстанавливать задачу. Статистика формируется раз в секунду, результаты приходят по мере нахождения. Приложение должно постоянно читать stdout.

- [Готовый Python-клиент](examples/backend_client.py) без сторонних зависимостей.
- [Команды backend и пример Node.js](docs/GUIDE.md#backend-integration).
- [Русское руководство по интеграции](docs/GUIDE.ru.md#интеграция-backend).
- [Rust SDK](examples/sdk.rs) и [расширение API скриптов](examples/sdk_script.rs).

Один процесс backend выполняет одну активную задачу. Для нескольких машин предусмотрен шардинг диапазона. Сиды передаются десятичными строками, чтобы не терять биты в JavaScript. При восстановлении возможен повтор последнего незавершённого участка; результаты можно различать по `seed_bits`.

## Производительность

Движок сначала проверяет дешёвые условия размещения, затем биомы и спавн. При переборе верхних 16 бит геометрия младших 48 бит переиспользуется. Скрипт компилируется один раз. Большие циклы отдельных фильтров можно выполнить нативно: например, проверка высоты прекращается на первой слишком низкой точке особняка.

Ниже — замеры на **Apple M2 Pro**, сборка 0.4.0 с оптимизацией C под CPU. Для каждого сценария выполнены прогрев и три запуска; показана медиана.

| Сценарий | Потоки CPU | Скорость |
|---|---:|---:|
| Только позиции особняка и деревни | 4 | 1 621 485 основ/с |
| Тот же запрос с Apple GPU | 4 | 1 760 274 основ/с |
| Деревня и пирамида с проверкой биомов | 10 | 90 373 сидов/с |
| Особняк от Y≈150, цикл в Rhai | 10 | 15 295 сидов/с |
| Тот же фильтр, нативный цикл | 10 | 48 265 сидов/с |
| Особняк от Y≈170, нативный цикл | 10 | 47 644 сидов/с |

Нативная и скриптовая проверки Y≈150 дали одинаковые пять результатов на одних и тех же 100 000 сидов. Отсев только по позициям значительно дешевле биомов и рельефа, поэтому его скорость нельзя переносить на любой запрос. Скорость на физической NVIDIA, Windows и Intel Mac пока не измерялась.

[Полный отчёт, разброс, команды и исходные измерения](benchmarks/README.md). В нём также есть раскрытие верхних битов и slime chunks.

## Сборка из исходников

Нужны stable Rust и C-компилятор: Xcode Command Line Tools на macOS, MSVC C++ Build Tools на Windows, GCC или Clang на Linux.

```sh
git clone https://github.com/D1ma-coder/MCFinder.git
cd MCFinder
cargo build --release --locked
cargo test --locked
```

Бинарник появится в `target/release`. Cubiomes включён в исходники; Cargo скачает Rust-зависимости при первой сборке.

Обычная сборка оптимизирует C под CPU машины сборки. На macOS/Linux `./scripts/build-native.sh` дополнительно настраивает Rust под этот CPU. Для переносимого бинарника используйте `cargo build --release --locked --no-default-features`.
